# v0.1.1 — 请求体风险与交接报告

本版本解决图片较多的会话在 token 上下文未满时被 provider `413 Request Entity Too Large` 终止，而悬浮窗无法提前解释风险的问题。

## 新增

- 统计当前会话图片数量、base64 图片载荷和模型可见请求体大小。
- 识别最近一次 413 请求体超限，并独立于上下文 token 百分比显示。
- 记录本会话已验证成功的最大请求体和已知失败的最小请求体。
- 右键菜单新增“生成交接报告”，输出本地 Markdown 报告。

## 风险判断

- 优先使用本会话的成功/失败边界，不跨会话套用固定硬限制。
- 缺少本会话证据时，使用 32MiB 预警和 42MiB 严重预警作为保守兜底。
- provider 网关、路由、压缩和实际序列化方式不同，可能造成不同会话的 413 阈值不同。

## 验证

- 10 项 Python 单元测试通过。
- 54MB、65 张图片的目标会话可识别约 56.1MB 请求体及 413 状态。
- 首次载荷分析约 121ms，后续缓存查询约 0.07ms。
